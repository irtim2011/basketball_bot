# Бот тренировок · 2.4.3

Telegram-бот на aiogram 3, SQLite и APScheduler. Работает на Ubuntu 24.04 как служба systemd; компьютер тренера можно выключать.

## Первый запуск на вашем сервере

Настройки находятся в `~/.config/training-bot/bot.env`. Нужны BOT_TOKEN, TRAINER_IDS, TIMEZONE (Europe/Moscow), POLL_OFFSET_MINUTES (180). Числовые ID двух администраторов разделяются запятыми; права у обоих одинаковые.

Самый простой вариант: загрузить **training-bot-update-2.4.3.sh** в текущую папку сервера через проводник VS Code Remote SSH, затем выполнить:

```bash
bash training-bot-update-2.4.3.sh
```

Установщик попросит пароль sudo, если он необходим. Он проверит токен, установит зависимости, выполнит тесты и включит службу `training-bot-dima.service` (имя зависит от пользователя). Настройки и база хранятся отдельно от версий кода.

Если скачали исходники из GitHub, распакуйте их, откройте папку проекта и выполните `bash install.sh`. Для приватного репозитория скачивание через браузер требует входа в GitHub.

Откройте [бота](https://t.me/Attendance_claude_bot), нажмите /start. На сервере должна работать только одна копия этого бота. Если он уже запущен где-то ещё, остановите прежнюю копию.

## Проверка за несколько минут

1. Пройдите регистрацию: ФИО → телефон. Telegram берётся из профиля автоматически.
2. Тренер открывает «Участники», выбирает себя и включает рассылку.
3. Нажмите «Тренировка» и создайте любую будущую тренировку.
4. Нажмите «Опрос сейчас», выберите тренировку и подтвердите отправку — ждать расписания не нужно.
5. Нажмите «Приду», затем «Таблица». Бот пришлёт ссылку, а в `Посещения_bot` появится Y.

Пока тренер не включил нового участника, тот не получает рассылку. Если тренер заранее добавил @username, регистрация подхватит его настройку рассылки. Люди без username также могут зарегистрироваться, после чего тренер включает их по ФИО.

## Интерфейс

- /menu, /help, **0** или «Показать действия» открывают кнопки.
- /start — регистрация; /profile — профиль и редактирование данных; /cancel — отменить незаконченный ввод.
- «Тренировка» / /training — календарь, время, разовая или еженедельная тренировка. Минуты можно выбрать кнопкой или ввести любое ЧЧ:ММ.
- «Расписание» / /schedule — расписание. Тренер нажимает тренировку и меняет или удаляет её. Изменение еженедельной записи относится ко всей серии будущих тренировок.
- «Участники» / /participants — включение и выключение рассылки; история сохраняется.
- «Участник» / /add — добавление по @username или Telegram ID, например 54545234. Можно несколько через пробел. Человек всё равно должен открыть бота и зарегистрироваться.
- /id — ваш Telegram ID. Отдельно бот выдаёт простой постоянный ID участника от 1001 до 9999; он виден в профиле, карточке и Google Таблице.
- «Опрос сейчас» / /poll_now — выбрать будущую тренировку и отправить опрос активным зарегистрированным участникам сразу. Есть подтверждение с числом новых получателей. Уже отправленные опросы не дублируются; отчёт приходит по завершении. При временной ошибке отправка повторяется до начала тренировки. Задание сохраняется после перезапуска.
- /version — версия запущенной копии; для этого обновления ожидается 2.4.3.
- «Таблица» / /table — обновляет Google Таблицу и присылает полный Excel со всеми листами: посещения, тарифы и номинальная доходность. На листе `Тарифы` красным отмечаются клиенты, у которых есть посещение, но тариф не заполнен.

Y означает «Приду», N — «Не приду», пустая ячейка — ответа ещё нет. Если в один день несколько тренировок, Y означает хотя бы один положительный ответ. Отдельного подтверждения тренером и отдельного журнала фактов нет.

`flag_active` вычисляется формулой самой таблицы: `active`, если в скользящие последние 30 дней у участника есть хотя бы одна отметка Y. Формула использует `TODAY()`, поэтому меняется автоматически с датой.

## Обновление без потери данных

Для каждой следующей версии замените загруженный `training-bot-install.sh` и снова выполните `bash training-bot-install.sh`. Либо используйте новый исходный код и `bash install.sh`.

Установка готовит новую папку версии, проверяет её и только затем перезапускает службу. Перед обновлением создаётся резервная копия базы. Старые версии автоматически не удаляются.

```bash
~/.local/bin/training-bot status
~/.local/bin/training-bot logs
~/.local/bin/training-bot diagnose
~/.local/bin/training-bot google-status
~/.local/bin/training-bot restart
~/.local/bin/training-bot stop
~/.local/bin/training-bot backup
~/.local/bin/training-bot rollback
```

Rollback возвращает предыдущую версию кода, сохраняя текущую базу. Резервные копии базы восстанавливаются отдельно при необходимости.

Папки:
- настройки: `~/.config/training-bot/bot.env`;
- база: `~/.local/share/training-bot/data/training_bot.db`;
- версии: `~/.local/share/training-bot/releases/`;
- копии базы: `~/.local/share/training-bot/backups/`.

При переносе существующей базы из старого архива сначала остановите старого бота и положите его `training_bot.db` в указанную папку данных до установки. Схема обновляется автоматически; старая посещаемость сохраняется. Старые кнопки опросов закрываются после обновления.

## Как работает рассылка

Расписание проверяется каждые 10 секунд. Опросы отправляются за 180 минут (3 часа) до начала, с погрешностью проверки и доставки Telegram. Если сервер перезапустился в течение этих трёх часов, он отправит ещё не отправленные опросы. После начала тренировки пропущенные опросы не отправляются.

Подтверждение нажатия отправляется до ожидания очереди действий. Запись ответа и сообщение об успехе выполняются после этого. Повторные одинаковые нажатия в пределах 0,8 секунды объединяются; из серии ожидающих команд меню выполняется последняя. Ввод ФИО и телефона сохраняет порядок. Старая кнопка календаря не может изменить новый диалог. Синхронизация Google Таблицы и рассылка выполняются в фоне. Сетевая задержка Telegram всё равно влияет на фактическую скорость. Ответ можно поменять до начала тренировки. Чужие и отменённые опросы не меняют данные. Действия тренера и личные данные доступны только в личном диалоге.

Повторные проверки обычно не дублируют отправку. При аварии в узком промежутке между отправкой Telegram и сохранением ID возможен повтор: Telegram не предоставляет ключ идемпотентности для sendMessage. Если пользователь заблокировал бота, рассылка для него отключается; после разблокировки тренер может включить её снова.

Перенос тренировки закрывает старый опрос; для нового времени придёт новый за 3 часа до начала. Отдельные уведомления об отмене и переносе пока не рассылаются. При перезапуске службы незаконченный диалог ввода нужно начать заново через /menu; сохранённые данные остаются.

## Разработка

Python 3.12. Зависимости зафиксированы в requirements.txt.
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
GOOGLE_SYNC_DISABLED=1 .venv/bin/python -m unittest discover -p 'test_*.py' -v
ENV_FILE=/путь/bot.env DB_PATH=/путь/test.db .venv/bin/python main.py
```

Тесты покрывают регистрацию, четырёхзначные ID, права, календарь, частые команды, мгновенное подтверждение кнопок, ручную рассылку, перезапуск, повторные попытки, границу 3 часов, объединение ответов Y/N и безопасное обновление Google Таблицы. Они работают на временной базе без реальных отправок Telegram и Google.

Источники API: [aiogram FSM](https://docs.aiogram.dev/en/v3.13.1/dispatcher/finite_state_machine/index.html), [Telegram answerCallbackQuery](https://core.telegram.org/bots/api#answercallbackquery).


## Что такое .sh и как применить обновление

.sh — текстовый файл с командами для оболочки Ubuntu. Самостоятельный установщик дополнительно содержит упакованные исходники. Команда `bash имя-файла.sh` выполняет установку или обновление. Настройки, участники и ответы хранятся отдельно и при обновлении сохраняются.

Загрузите новый `training-bot-update-2.4.3.sh` в `/home/dima/projects/training_attendance_bot` через VS Code Remote SSH, затем:

```bash
bash /home/dima/projects/training_attendance_bot/training-bot-update-2.4.3.sh
```

После запуска откройте /version в Telegram — должно быть 2.4.3. Затем /menu → «Опрос сейчас».

## Два администратора и смена токена

Два ID администраторов и токен меняются командой `~/.local/bin/training-bot configure`. Enter сохраняет текущие значения. ID ассистента: 440415724; ID главного тренера нужно взять из его команды /id. Не подставляйте пример 54545234 без проверки владельца.

Токен перевыпускается для прежнего бота в @BotFather: /mybots → нужный бот → API Token → Revoke current token. После отзыва старый токен перестаёт работать; вставьте новый в установщик. Ввод скрыт, токен проверяется через getMe и не попадает в командную строку, исходники или GitHub. Источник: https://core.telegram.org/bots/tutorial

Позже настройки можно поменять одной командой: `~/.local/bin/training-bot configure`. Она проверит токен, сохранит настройки и перезапустит службу. Участники и ответы остаются в прежней SQLite-базе.

## Google Таблица

Бот изменяет только лист `Посещения_bot` в таблице `1YNdUTiRQZ5q_NFu8dlNGDqTbSV3nmwZseq4ZIwy2s_g`. Другие листы остаются свободными для любых расчётов. Обновление идёт в фоне и не задерживает ответ на кнопку Telegram. Несколько быстрых ответов объединяются в одну синхронизацию.

Финансовая модель хранится в отдельных листах. В `Покупки тарифов` тренер заполняет жёлтые колонки: дату, ID участника, число купленных тренировок и при необходимости комментарий. ФИО, тариф и доход подставляются автоматически. `Фактическая прибыль` группирует доход по датам покупок, а расход 600 ₽ за каждое посещение показывает одной суммой в последний календарный день месяца. На листе `Номинальная доходность` ниже дневного расчёта выводятся активные клиенты и экспериментальный список риска ухода. Активность означает хотя бы одно посещение за последние 30 дней; риск ухода — минимум два посещения в предыдущие 30 дней и ни одного в последние 30 дней. Служебный лист `Аналитика_тех` скрыт.

Повторно создать или восстановить формулы финансовых листов можно командой `~/.local/bin/training-bot finance-setup`. Ввод на листе `Покупки тарифов` сохраняется.

Для доступа с Ubuntu нужен сервисный аккаунт Google Cloud: включите Google Sheets API и Google Drive API, создайте JSON-ключ и загрузите его на сервер. Затем одной командой установите ключ:

```bash
~/.local/bin/training-bot google-connect /путь/к/google-service-account.json
```

Таблица должна быть открыта адресу `client_email` из JSON как редактору. Проверка без изменений: `~/.local/bin/training-bot google-status`. JSON хранится в `~/.config/training-bot/google-service-account.json` с правами 600 и не попадает в обновления, архивы исходников или GitHub.

При обновлении старой базы бот автоматически выдаёт существующим и новым участникам свободные четырёхзначные ID. Если в исторической строке Google Таблицы позже заполнить Telegram ID, бот сопоставит её по Telegram ID и сохранит четырёхзначный ID этой строки.

## Если ответы чередуются между старой и новой версией

Это признак нескольких процессов с одним токеном. Разные базы в этих процессах объясняют, почему человек то зарегистрирован, то нет. Очередь действий внутри одной копии не может породить тексты из другой версии.

При обновлении установщик ищет доступные ему Python-процессы с start_polling и точно тем же BOT_TOKEN, останавливает старые копии и отключает их службу только если PID является основным процессом этой службы. SSH и VS Code как родительские службы не останавливаются. Старые базы и файлы не удаляются и не объединяются автоматически.

Блокировка не даёт одновременно запустить две новые копии под одним пользователем на сервере. Если Telegram сообщает о конкурирующей копии на другой машине, новая служба прекращает polling с кодом 73 и не перезапускается циклически. Выполните `~/.local/bin/training-bot diagnose`, остановите лишнюю копию и затем `~/.local/bin/training-bot restart`. Проверка на сервере не видит процесс на другом компьютере и не распознаёт токен, зашитый прямо в исходнике или скрытый внешним менеджером секретов.
